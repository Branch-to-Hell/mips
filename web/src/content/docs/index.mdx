## One processor, three levels

The same CPU and the same system (`rtl/life_system.v`) run all three. Each level only adds what the previous one didn't need.

## In numbers

| | |
|---|---|
| CPU | 5-stage pipeline (IF, ID, EX, MEM, WB), hazard unit, 1 branch delay slot, 25 MHz |
| Instructions | The 12 required + the rest of the MIPS I integer set (~50), so GCC's code runs |
| Game of Life build | 5,528 logic elements (11 % of the FPGA), 26 % of the memory bits, 7.6 ns of setup slack |
| Doom build | 8,018 logic elements (16 %), 147 of 182 memory blocks, 5.4 ns of setup slack |
| Doom | **Runs on the board**: title screen, demo and a playable game (Nov 26). In simulation: title 1.15 s after KEY0, ~7.8 frames per second |
| Tests | Every case of the professor's list, all PASS ([tests](/tests/)) |

## Graded version

The version we hand in is the tag **[`final-submission`](https://github.com/Branch-to-Hell/mips/tree/final-submission)**: the code, the memory images and this report exactly as they were graded. `main` may keep changing after that; the tag doesn't.
