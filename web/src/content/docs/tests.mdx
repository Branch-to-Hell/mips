:::tip[In 30 seconds]
- Every test runs on **`mips_pipeline` inside `life_system`**, the same hardware that goes to the board, and **checks itself**: it prints `PASS` or `FAIL`.
- There is at least **one case per instruction**, every **integration** case of the spec's list, an **assembler error** and an **invalid access**.
- One **trace per format** (R, I, J) follows an instruction through the 5 stages, cycle by cycle.
:::

Two more checks that compare our CPU with an independent reference:

- **MARS drill** (`src/tools/drill.py`): runs a MARS program in MARS and on our CPU in ModelSim and compares every register and the data. It's how we answer "run this unseen program" in under 15 minutes (`docs/tc12_drill.md`).
- **Trace comparison** (Verilator, WSL): `make -C verif/verilator compare PROG=<name>` runs a program on our CPU and on our Python reference simulator and compares every register write. This is how C programs, and later Doom, were checked.

|---|---|---|
| `add` | R | `tc4_rtype`: 1, 2 · trace R · `cpu11` |

| `and` | R | `tc4_rtype`: 5 |
| `or` | R | `tc4_rtype`: 6 |
| `slt` | R | `tc4_rtype`: 9 to 12 (signed) |
| `addi` | I | `tc4_itype`: 1, 2 · `cpu11` |
| `ori` | I | `tc4_itype`: 5, 6, 12 |
| `lw` | I | `tc4_memory`: 1 to 10 · trace I |
| `sw` | I | `tc4_memory`: 1 to 9 |
| `beq` | I | `tc4_branches`: 1, 2, 5, 6, 8 |
| `j` | J | `tc4_jumps`: 1, 4 · trace J |

Each `tc4_*` program stores its results in data memory and the testbench compares them with the expected values written in the program.

## Traces (R, I, J)

`trace.do` runs `src/programs/tc16_trace.asm` and writes one block per clock cycle for one instruction of each format: the state before, **IF** (PC, the 4 bytes, the word), **ID** (IF/ID, fields, extended immediate, every control signal, the operands, stall and redirect), **EX** (ID/EX, ALU inputs and result), **MEM** (EX/MEM, memory bus), **WB** (MEM/WB, register write), and the state after. The testbench also checks each result and that the instruction took 5 consecutive cycles.

| Trace | Instruction | PC | Result |
|---|---|---|---|
| [`trace_R.txt`](https://github.com/Branch-to-Hell/mips/blob/main/verif/traces/trace_R.txt) | `add $t2, $t0, $t1` | `0x1C` | `$t2` = 5 + 7 = `0x0000000C` |
| [`trace_I.txt`](https://github.com/Branch-to-Hell/mips/blob/main/verif/traces/trace_I.txt) | `lw $t3, 4($s1)` | `0x20` | `$t3` = mem[`0x1001_0004`] = `0xCAFE1234` |
| [`trace_J.txt`](https://github.com/Branch-to-Hell/mips/blob/main/verif/traces/trace_J.txt) | `j j_target` | `0x24` | IF fetches the delay slot (`0x28`), then `0x30`; `$t4` stays 0 |

## How to reproduce everything

From the repository root (PowerShell), assemble the test programs once:

```powershell
foreach ($p in "tc4_rtype","tc4_itype","tc4_shifts","tc4_memory","tc4_branches","tc4_jumps","tc5_data_hazards","tc5_load_use","tc5_branch_hazards","tc5_jump_hazards","tc16_trace","test_halt","count_value_in1","count_value_in2","count_value_in3") { python src/assembler/assembler.py src/programs/$p.asm }
```

Then run the testbenches from `verif/`:

```powershell
cd verif
foreach ($t in "tc4","tc5","tc15","trace","instruction_memory","cpu11","cpu14","halt","cpu6") { vsim -c -do "do $t.do; quit -f" | Select-String "PASS|FAIL" }
cd ..
python src/tools/check_asm_errors.py
```
